## 1. 土砂災害リスク区域の通行制御

### 概要
土砂災害特別警戒区域等の危険性が高い部分を、NavMeshと連携して通行不可または回避対象にする機能。

### 目的
- 地震後の二次災害リスクが高い区域を避難経路から除外
- より現実的な避難行動のシミュレーション

### 実装方法の候補

- [ ] **方法A: NavMeshObstacle動的生成**
  - 実行時に土砂災害特別警戒区域のBoundsに基づいてNavMeshObstacleを生成
  - メリット: 災害フェーズに応じて動的に制御可能
  - デメリット: 大量のObstacle生成によるパフォーマンス低下の懸念

- [ ] **方法B: NavMesh Area設定（事前Bake）**
  - 土砂災害区域を別のNavMesh Areaとして設定し、コストを高く設定
  - メリット: 実行時の負荷が低い
  - デメリット: シーンごとにNavMeshのRe-Bakeが必要

- [ ] **方法C: エージェント側での回避判断**
  - NavMeshを変更せず、Evacuee側で経路上の土砂災害区域を検出し回避
  - メリット: NavMesh変更不要、実装が比較的容易
  - デメリット: 最短経路計算には反映されない

### 関連ファイル
- `Assets/Scripts/EnvironmentalContextProvider.cs` - 土砂災害区域の判定
- `Assets/Scripts/GeoSpatialIndex.cs` - 土砂災害データの保持
- `Assets/Scripts/Evacuee.cs` - 避難者の経路制御

## 2. DEM（地形）データの高度な活用

### 概要
現在は概算標高のみ取得しているDEMデータを、傾斜情報や高台方向の判定に活用する。

### 実装項目

- [ ] **傾斜角度の計算**
  - DEMメッシュの頂点データから傾斜角度を算出
  - GeoSpatialIndexBaker.csでBake時に計算
  - TerrainEntryに`averageSlope`, `maxSlope`フィールドを追加

- [ ] **高台方向の判定**
  - 現在位置から見て標高が高い方向を算出
  - 津波避難時の「高台へ向かう」判断に利用

- [ ] **坂道の認識と経路選択への反映**
  - 「この先は急な坂道がある」等の環境認識表現
  - 高齢者・身体障害者の経路選択への影響

- [ ] **正確な標高取得（レイキャスト）**
  - 現在のBounds平均ではなく、DEMメッシュへのレイキャストで正確な標高を取得

### 関連ファイル
- `Assets/Scripts/GeoSpatialIndex.cs` - TerrainEntryの拡張
- `Assets/Editor/GeoSpatialIndexBaker.cs` - 傾斜計算の追加
- `Assets/Scripts/EnvironmentalContextProvider.cs` - 傾斜取得メソッドの追加

## 7. 交通シミュレーションの導入

### 概要

車両避難時の渋滞・交通状況を再現し、避難者の意思決定に交通情報を反映させる。
現状のシステムはNavMeshベースの歩行者移動のみであり、交通ネットワーク（車線・交差点の挙動）は実装されていない。

### 背景と課題

#### PLATEAUの交通シミュレーション機能の制約

PLATEAUのToolkit（Unity SDK）はLOD3道路データがあれば道路ネットワーク生成と交通シミュレーションを実行可能（参考: [PLATEAUの交通シミュレーション実装](https://note.com/vrsensei/n/nc821e64157f9)）。しかし以下の理由から、現状のプロジェクトでは利用困難：

- **LOD3対応道路が極めて少ない**: LOD3に対応している道路データは全国的にも限定的で、対象範囲も狭い
- **福島県の道路データはほぼLOD1**: シミュレーション対象地域（いわき市・浪江町・南相馬市）の道路データはLOD1が大半
- **LOD1の限界**: LOD1は道路のポリゴン（面）のみで、車線情報・方向・接続関係を持たない

#### 道路メッシュのつぎはぎ問題

- PLATEAUの道路オブジェクトは個々のポリゴンとして分断されており、連続した道路ネットワークとして接続されていない
- ルールベースで車線を定義しても、特に**交差点で接続が破綻**する
- `Assets/Editor/RoadSnapper.cs` で高さ調整は実施済みだが、ネットワークとしての接続性は未解決

#### 交通シミュレーション不在の影響

- **渋滞による避難遅延・心理的影響**（焦り・ルート変更判断）が再現できない
- 車避難と徒歩避難の混在シナリオが表現できない
- LLMエージェントの意思決定に「交通状況」という重要な入力情報がない
- 避難時のボトルネック（渋滞時の心理状態変化）の再現が本シミュレーションの重要課題

### 現状のシステムが保持している道路情報

現在 `GeoSpatialIndex` / `RoadEntry` が持つ属性：

| 属性 | 内容 |
|------|------|
| `name` | 道路名 |
| `position` | 中心座標（Vector3） |
| `functionCode` | 機能コード（1=高速, 2=国道, 3=県道, 4=市町村道 等） |
| `sectionType` | 区間種別（1=土工, 2=高架橋, 3=橋梁, 4=交差部, 5=アンダーパス, 6=トンネル） |
| `gmlId` | PLATEAU GML ID |

→ **車線数・方向・交差点接続情報は無い**

### 改善案

#### 案A: 外部の道路ネットワークデータの紐づけ（実現可能性：中〜高）

**OpenStreetMap (OSM)** または**国土数値情報**の道路ネットワークデータを活用する：

- [ ] **OpenStreetMap連携**
  - OSMは車線数・一方通行・速度制限・交差点接続情報を保持
  - `osm2unity` やOSMSharpなどのライブラリでUnityに取り込み可能
  - PLATEAUの道路ポリゴン位置と座標マッチングで紐づけ
  - 利点: 全世界カバー、福島県含む、無料
  - 課題: 座標のズレ補正、LOD1メッシュとの視覚的整合性

- [ ] **国土数値情報の道路データ活用**
  - 国土交通省の[国土数値情報](https://nlftp.mlit.go.jp/)に道路中心線・ネットワークデータあり
  - GeoJSON/Shapefile形式で提供
  - 道路種別・車線数・幅員情報を含む場合がある

#### 案B: LOD1道路ポリゴンからの交通ネットワーク自動生成（実現可能性：中）

- [ ] **道路ポリゴンの中心線抽出**（スケルトン化）
- [ ] **中心線の交点を交差点ノードとして定義**
- [ ] **道路幅から車線数を推定**
- [ ] **簡易的な交通流シミュレーション**（セルオートマトン等）を適用
- 課題: 交差点の接続ルール定義が複雑、精度の担保

#### 案C: 交通の抽象化モデル（実現可能性：最も高）

交通ネットワークを完全に再現せず、統計的・確率的モデルとして渋滞を表現する：

- [ ] **主要道路ごとに時間帯別の混雑度パラメータを設定**
- [ ] **避難者密度から動的に渋滞レベルを計算**
- [ ] **LLMへのコンテキストに交通状況を提供**（例:「周辺の交通状況：渋滞レベル3/5」）
- 利点: 現在のアーキテクチャへの変更が最小限、短期間で実装可能
- 課題: 視覚的な渋滞表現は限定的

### 関連ファイル
- `Assets/Scripts/GeoSpatialTypes.cs` - RoadEntry / RoadContext の定義
- `Assets/Scripts/GeoSpatialIndex.cs` - 道路データの空間インデックス
- `Assets/Scripts/EnvironmentalContextProvider.cs` - `GetNearbyRoads()`, `GetNearestMajorRoad()`
- `Assets/Editor/GeoSpatialIndexBaker.cs` - PLATEAU `tran_` オブジェクトからのデータ抽出

- `Assets/Scripts/Evacuee.cs` - NavMeshAgent による避難者移動
- `Assets/Scripts/FireTruckAgent.cs` - 消防車NavMesh巡回

## 6. ペルソナによる環境認識の差異

### 概要
避難者のペルソナ（土地勘レベル、年齢、過去の災害経験等）に応じて環境認識の詳細度を変える。

### 実装項目

- [ ] **土地勘レベルによる差異**
  - native: 詳細な土地知識（「この先の崖は昔崩れたことがある」）
  - resident: 一般的な土地知識
  - newcomer: 見た目の情報のみ

- [ ] **過去の災害経験による差異**
  - 経験者: 危険箇所をより強く認識
  - 未経験者: 危険の認識が薄い

### 関連ファイル
- `llm_server/server.py` - ペルソナに応じたプロンプト分岐
