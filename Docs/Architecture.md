# LLM駆動避難シミュレーション アーキテクチャ

## 1. システム概要

本システムは、**大規模言語モデル（LLM）を認知エンジンとして活用したマルチエージェント避難シミュレーション**である。Unity上で構築され、大規模災害時の人間の避難行動を再現することを目的とする。地理情報には国土交通省のPLATEAUデータを活用し、福島県いわき市の実際の建物・地形を再現している。

### 設計思想

従来の避難シミュレーションが「合理的な最適避難行動」を前提とするのに対し、本システムは**人間らしい多様な行動**を再現する：

- **心理的バイアス**: 正常性バイアス（危険の過小評価）、同調バイアス（周囲への追従）
- **社会的相互作用**: 家族の合流、情報共有、周囲との会話
- **状況認識**: 災害情報の受信、周囲の状況把握

2011年東日本大震災の観察データに基づき、避難の遅延、家族の探索、コミュニケーションといった実際に観測されたパターンを再現する。

## 3. PLATEAUデータの活用

### 3.1 PLATEAUとは

PLATEAU（プラトー）は国土交通省が主導する3D都市モデル整備・活用プロジェクト。本システムでは福島県いわき市のPLATEAUデータを活用している。

### 3.2 利用しているPLATEAUデータ

| データ種別 | 取得情報 | シミュレーションでの用途 |
|-----------|---------|------------------------|
| **建物モデル（LOD1/LOD2）** | 建物の3D形状、位置座標 | 避難者の初期配置、建物内外の判定 |
| **建物用途** | 住居、商業、学校、病院など | 避難者のスポーン位置（住宅地、オフィス街、学校）の分類 |
| **建物高さ** | 建物の高さ（m） | 垂直避難可能性の判定 |
| **建物構造** | 木造、鉄筋コンクリートなど | 耐震性の推定 |
| **床面積** | 各階の床面積 | 避難所の収容人数計算 |
| **地形モデル（DEM）** | 標高データ | 海抜の取得、津波リスクの判定 |

### 3.3 避難所収容人数の計算

PLATEAUの床面積データを用いて、避難所の収容人数を算出：

```
収容人数 = 床面積 × 0.8（有効利用率）÷ 1.65m²（1人あたり面積）
```

## 5. 避難者の行動モデル

### 5.1 選択可能な行動

避難者は以下の6種類の行動から選択する：

| 行動 | 説明 |
|------|------|
| **避難** | 指定した避難所へ向かって移動する |
| **待機** | 現在地にとどまり、状況を見守る |
| **家族探索** | シミュレーション内に存在する家族を探し、追いかける |
| **連絡** | 電話やメッセージで家族に連絡を取る |
| **追従** | 合流した家族や知人について行動する |
| **会話** | 近くにいる他の避難者と情報交換する |

### 5.2 避難者の状態

| 状態 | 説明 |
|------|------|
| **体力** | 移動速度に影響。走り続けると消耗する |
| **ストレス** | 判断に影響を与える心理的負荷 |
| **エネルギー** | 全体的な活動能力 |

### 5.3 移動速度の選択

| 速度 | 説明 | 体力消耗 |
|------|------|---------|
| **ゆっくり** | 高齢者や身体に制約がある場合 | 低 |
| **通常** | 一般的な歩行速度 | 低 |
| **早歩き** | 急いでいるが走らない | 中 |
| **走る** | 全力で移動 | 高 |

### 5.4 家族合流の流れ

```
家族探索を開始
      │
      ▼
 10秒間隔で家族の位置を追跡
      │
      ▼
 家族との距離が10m以内？
    │      │
   はい    いいえ
    │      │
    ▼      └──▶ 追跡を継続
 追従行動に移行
（一緒に避難）
```

## 6. 個人属性（ペルソナ）

各避難者には以下のような個人属性が設定される（500人分のデータを使用）：

| 属性 | 例 | 意思決定への影響 |
|------|-----|-----------------|
| **名前** | 山田 太郎 | 識別用 |
| **年齢層・性別** | 60代・男性 | 移動速度、判断傾向 |
| **移動能力** | 標準の0.7倍 | 実際の移動速度 |
| **心理状態** | 正常性バイアス・楽観的 | 危険の認識度合い |
| **行動優先度** | 様子見・現状維持 | 初期行動の傾向 |
| **地域熟知度** | 長年の居住者 | 避難所・地形の知識 |
| **災害経験** | 2011年の津波を経験 | 危機感の度合い |
| **身体状況** | 杖を使用 | 移動制約 |
| **自宅の海抜** | 5m | 津波リスクの認識 |

### 年齢分布

いわき市の人口統計に基づき、60代以上が約35%を占める高齢化地域を再現。

### 心理状態の分布

| 心理状態 | 割合 | 特徴 |
|---------|------|------|
| 冷静系 | 30% | 状況を客観的に判断 |
| 正常性バイアス | 25% | 危険を過小評価しがち |
| 同調系 | 20% | 周囲に合わせて行動 |
| 焦燥 | 10% | パニックになりやすい |
| 慎重 | 15% | 石橋を叩いて渡る |

## 9. 意思決定の仕組み

### 9.1 LLMを用いた意思決定

各避難者の意思決定は、大規模言語モデル（LLM）によって行われる：

```
避難者の状態変化
      │
      ▼
┌─────────────────────────────────────┐
│ 意思決定リクエストの作成              │
│                                     │
│ ・個人属性（年齢、心理状態、経験）     │
│ ・現在の状況（位置、体力、ストレス）   │
│ ・周辺情報（避難所、他の避難者）       │
│ ・家族情報（位置、連絡状況）          │
│ ・過去の行動履歴                     │
└─────────────────────────────────────┘
      │
      ▼
  Python意思決定サーバーへ送信
      │
      ▼
┌─────────────────────────────────────┐
│ LLMによる判断                        │
│                                     │
│ 「この人物ならどう行動するか」を       │
│ ペルソナに基づいて推論               │
│                                     │
│ ※「最適な判断」ではなく             │
│ 　「その人らしい判断」を生成         │
└─────────────────────────────────────┘
      │
      ▼
  行動決定（避難/待機/探索/連絡/追従/会話）
```

### 9.2 階層的な思考構造

LLMは以下の3層で思考するよう設計されている：

| 層 | 内容 | 例 |
|-----|------|-----|
| **長期目標** | 最終的に達成したいこと | 「家族全員で高台の避難所に到達する」 |
| **中期計画** | 目標達成のための手順 | 「まず学校で子供を迎えに行く」 |
| **即時行動** | 今この瞬間に取る行動 | 「学校に向かって移動する」 |

### 9.3 プロンプト設計の特徴

| 特徴 | 説明 |
|------|------|
| **一般市民として振る舞う** | 「最適な避難者」ではなく「災害時の一般市民」として応答 |
| **人間らしい反応を許容** | パニック、家族への心配、危険の過小評価なども許容 |
| **具体的な状況を提示** | 距離を「すぐ近く」「歩いて10分」など自然な表現に変換 |
| **利用可能行動の明示** | 選択できる行動と選択できない行動を明確に提示 |

### 9.4 ルールベースの意思決定（比較用）

LLMとの比較実験のため、単純なルールに基づく意思決定も実装されている：

```
1. 津波警報を受信した？ → 最寄りの避難所へ避難
   ※地震だけでは避難しない

2. 近くに合流していない家族がいる？ → 家族を探索
   （子供 > 配偶者 > その他 の優先度）

3. 連絡していない家族がいる？ → 1回だけ連絡

4. 長時間待機している？ → 強制的に避難（10分後）

5. 上記に該当しない → 待機
```

## 10. 社会的相互作用

### 10.1 家族探索

- シミュレーション内の家族のみ探索可能
- 10秒間隔で相手の位置を追跡
- 10m以内に近づくと「合流」と判定
- 合流後は一緒に行動（追従）

### 10.2 連絡（電話・メッセージ）

- シミュレーション内外の家族と連絡可能
- 最大10往復の会話が可能
- 通信には遅延がある（3秒）
- 会話中は移動を停止

### 10.3 会話（近隣者との情報交換）

- 30m以内の他の避難者と会話可能
- 最大10往復の会話
- 通信には遅延がある（5秒）
- 双方が終了を望むまで継続
- 会話を通じて避難行動が変化する可能性

### 10.4 追従

- 家族と合流後に自動的に開始
- 5mの距離を維持しながら移動
- 相手の目的地に従う
- 循環追従（A→B→A）の検出・防止機能あり

## 11. 災害シナリオ

### 11.1 シナリオの種類

| シナリオ | 地震の強さ | 津波警報 | 想定される避難者行動 |
|----------|-----------|----------|---------------------|
| **震度2** | 弱い揺れ | なし | 多くが待機 |
| **震度6** | 強い揺れ | なし | 行動が分かれる |
| **震度7+津波** | 激しい揺れ | **あり** | 避難行動が活発化 |

### 11.2 イベントの流れ（例）

| 経過時間 | イベント |
|----------|----------|
| 0秒 | 地震発生 |
| 60秒 | 緊急地震速報（Jアラート） |
| 120秒 | 行政無線による避難指示 |
| 600秒 | 避難所の開設 |
| 1800秒 | 避難完了期限（30分） |

## 12. 実験設計

### 12.1 実験1: LLM vs ルールベース比較

| 項目 | 内容 |
|------|------|
| **目的** | LLMによる意思決定とルールベースの比較 |
| **仮説** | LLMは人間らしい多様な行動を再現し、ルールベースは合理的だが画一的 |
| **条件数** | 2条件（LLM / ルールベース） |
| **測定指標** | 避難完了率、避難完了時間、行動の多様性 |

### 12.2 実験2: 認知バイアスの影響

| 条件 | 説明 |
|------|------|
| **バイアスなし** | 基準となる条件 |
| **正常性バイアスのみ** | 「大したことない」と思い込む傾向 |
| **同調バイアスのみ** | 周囲に合わせる傾向 |
| **両バイアス** | 両方の傾向を持つ |

### 12.3 実験3: 情報提供戦略の検証

行政からの情報提供方法を変えた場合の避難行動への影響を検証：

| 条件 | 情報の具体性 | 表現の切迫感 |
|------|-------------|-------------|
| **標準** | 一般的 | 通常 |
| **切迫強調** | 一般的 | 強く警告 |
| **詳細情報** | 避難所名・海抜を明示 | 通常 |
| **詳細+切迫** | 避難所名・海抜を明示 | 強く警告 |

東日本大震災の教訓（初報の過小評価、指定避難所の限界、事前知識の上書き困難）を背景に設計。

## 13. 計測指標

### 13.1 主要指標

| 指標 | 説明 |
|------|------|
| **避難完了率** | 避難所に到達した避難者の割合 |
| **平均避難時間** | 避難所到達までの平均時間 |
| **避難所別利用率** | 各避難所の選択割合 |
| **行動種別頻度** | 各行動（避難、待機、探索等）の発生回数 |
| **生存率** | 津波到達時に安全な高度にいた避難者の割合 |

### 13.2 生存判定

津波到達時の位置の海抜が「津波の高さ × 2」以上であれば生存と判定。これは2011年の実際の生存データに基づく安全マージン。

### 13.3 出力ファイル

| ファイル | 内容 |
|---------|------|
| **エピソード要約** | 各シミュレーション回の集計結果 |
| **条件別統計** | 実験条件ごとの平均・標準偏差 |
| **LLM決定ログ** | 個々の意思決定の詳細（JSON形式） |

| 工夫 | 説明 |

## 16. 重要な設計判断

### 16.1 LLM優先とフォールバック

「正しい」避難行動をプログラムで強制せず、LLMに判断を委ねる。APIが利用できない場合でもシステムが動作するようフォールバック機能を実装。

### 16.2 現実的な体力消耗

長距離を走り続けると体力が消耗し、速度が低下する。現実の避難行動を再現。

### 16.3 シミュレーション外家族の探索除外

Unity上に存在しない家族は探索できない。連絡のみ可能とすることで、現実的な制約を再現。

### 16.4 階層的な思考の促進

LLMに「今何をすべきか」だけでなく「最終的に何を達成したいか」「そのための計画は何か」も考えさせることで、一貫性のある行動を生成。

### 16.5 多様なペルソナによる行動の多様性

500人それぞれに異なる個人属性を設定することで、明示的なランダム化なしに行動の多様性を実現。

### 16.6 複数回のやり取りが可能な会話

1回の連絡・会話で終わらず、最大10往復のやり取りを可能にすることで、現実的な社会的相互作用を再現。

### 16.7 PLATEAUデータに基づく空間再現

国土交通省のPLATEAUデータを活用することで、いわき市の実際の建物配置、地形、海抜を忠実に再現。避難シミュレーションの現実性を向上。

### 16.8 海抜に基づく生存判定

2011年東日本大震災の実際の生存データに基づき、「津波の高さの2倍以上の海抜」を生存ラインとして設定。PLATEAUのDEM（数値標高モデル）データを活用。

### 16.9 SUMO交通シミュレーション統合

OSMの道路ネットワークとSUMO交通シミュレータを統合し、車両による避難行動と渋滞を再現。

- **データパイプライン**: OSM → osmnx → GeoJSON → Unity / OSM → netconvert → SUMO
- **座標変換**: WGS84 → JGD2011平面直角座標第9系 → PLATEAU Unity座標
- **通信**: Python WebSocketブリッジ（TraCI経由でSUMOと接続）
- **移動モード**: 避難者は車両(DRIVING)と徒歩(WALKING)を選択可能
- **渋滞モデル**: BPR関数ベースの渋滞レベル(1-5)をリアルタイム計測
- **LLM統合**: 渋滞情報をLLMプロンプトに自然言語で提供し、ルート変更や車両放棄の判断に反映
- **可視化**: 道路ヒートマップ（緑=順調、赤=渋滞）でボトルネックを視覚化
